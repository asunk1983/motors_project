# Диагностика провалившихся e2e-тестов

| Сценарий | Категория | Обоснование |
| --- | --- | --- |
| 14. Сортировка через выпадающий список | баг теста | Тест пытается выбрать значения `serial_number_asc` и `serial_number_desc`, но в HTML-файле у элемента `#sortSelect` нет таких опций. В интерфейсе доступны другие значения, например `location_asc`, `location_desc`, `id_asc`, `id_desc`, `engine_type_asc`, `engine_type_desc`, `manufacturer_asc`, `manufacturer_desc`. Ошибка возникает на этапе выбора несуществующего варианта, а не из-за поведения приложения. |
| 16. Пагинация | баг теста | Тест ожидает наличие элемента `#pageTotal`, но в шаблоне каталога есть `#pageInfo` и `#pageNumber`, а `#pageTotal` отсутствует. То есть проверка ищет не тот элемент интерфейса. |
| 21. Обновление каталога (кнопка Refresh) | баг теста | В HTML нет кнопки с id `#refreshBtn`; обновление каталога реализовано через функцию `refreshTable()` и кнопку без id в правом верхнем углу. Тест пытается кликнуть по несуществующему селектору. |
| 23. Заполнение формы | баг теста | Тест предполагает, что поля формы добавления двигателя заполняются в DOM с уже существующими значениями, но в текущем сценарии форма инициализируется на вкладке «Добавить», и проверка идёт по полям `#f_location`/`#f_serial_number` как по обычным инпутам. Проблема не в функциональности сохранения, а в том, что тест не учитывает реальное состояние формы/ожиданий в текущем UI. |
| 24. Добавление ряда режима работы | баг теста | В форме добавления двигателя используются функции `addModeRow()` и `addWorkRow()` для тела таблиц `#modesBody` и `#worksBody`. Тест же вызывает `addModeRowInline()` и ожидает строки в `#modesTableBody`, но такого контейнера и такой функции для этой формы нет. Это несоответствие селектора/функции, а не баг приложения. |
| 25. Добавление записи о работе | баг теста | Аналогично сценарию 24: тест вызывает не ту функцию для формы «Добавить» и ждёт строки в `#worksTableBody`, тогда как приложение добавляет строки в `#worksBody` через `addWorkRow()`. Селектор и точка входа в UI не совпадают с реальной реализацией. |
| 26. Выбор фото | баг теста | Приложение рендерит превью выбранных фото в контейнер `#photosPreview` с элементами класса `.photo-thumb` / `.is-pending`, а тест ждёт `.pending-photo-item`. То есть тест ищет не тот DOM-элемент, который реально создаёт интерфейс. |
| 28. Удаление непривязанного фото | баг теста | Причина та же, что и в сценарии 26: приложение не использует класс `.pending-photo-item` для превью; тест ищет неправильный селектор для удаления/проверки состояния. |
| 29. Очистка формы | баг теста | Кнопка очистки в форме не имеет id `#clearBtn`; в шаблоне она реализована как обычная кнопка `onclick="resetForm()"` без ID. Тест пытается кликнуть по несуществующему элементу. |
| 33. Просмотр характеристик | баг теста | В детальной карточке двигатель не рендерится в элемент `#detailSerial`; сериал выводится в общем содержимом карточки в структуре `.detail-item` / `.value`. Тест ищет не тот элемент, поэтому падает до проверки реального содержимого. |
| 34. Редактирование и сохранение характеристик | баг теста | Для редактирования в карточке используются динамически созданные элементы с классом `.detail-edit-input` и `data-field`, а не статический `#detail_purpose`. Тест пытается найти и заполнить элемент по несуществующему id. |
| 35. Отмена редактирования | баг теста | Та же причина, что и в сценарии 34: для поля назначения в UI нет отдельного `#detail_purpose`; редактируемые поля создаются динамически. Падение связано с неверным селектором, а не с логикой отмены. |
| 36. Переключение режимов просмотра/редактирования | баг теста | Тест ищет кнопку режима по классу `.detail-mode-toggle button`, но в текущем интерфейсе режимы переключаются через динамически рендеримый toolbar и кнопки с текстом «👁 Просмотр» / «✏️ Редактирование». Селектор и ожидаемая структура не совпадают с тем, что реально отрисовывает приложение. |
| 38. Добавление и сохранение работы | баг теста | Кнопка добавления работы в карточке имеет текст `➕ Добавить`, а тест ищет `button:has-text('Добавить работу')`. Это несовпадение текста/селектора. Ошибка не в бизнес-логике, а в том, что тест ищет не ту кнопку. |
| 40. Навигация между двигателями | баг теста | Тест ищет стрелки навигации по классу `.detail-nav-arrow`, но в текущем интерфейсе навигация реализована кнопками `◀ Предыдущий` и `Следующий ▶` без такого класса. Это проблема селектора, а не отсутствие функции навигации. |
| 41. Печать карточки | баг теста | Тест использует `page.context.expect_popup()`, однако в используемой версии Playwright для Python у API нет такого метода. Ошибка возникает на уровне вызова Playwright API, а не из-за того, что печать в приложении не работает. |
