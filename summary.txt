ПРОБЛЕМА: после разворачивания старой БД в комбобокс «Все разделы» журнала не добавляются
разделы скорректированных записей; «внесённые изменения» в старую базу не доезжают.
Дата: 2026-09-12. Режим: Act (правка применена, коммит не делал).

======================== ДИАГНОЗ — ДВЕ РАЗНЫЕ ПРИЧИНЫ ========================

ПРИЧИНА 1 (главная, ИСПРАВЛЕНА): разовый кэш-флаг auditEntityTypesLoaded.

Комбобокс «Все разделы» строится из SELECT DISTINCT entity_type FROM audit_log
(audit_repo.py:119-126) — разделы появляются «по мере появления записей».
Но в static/js/audit.js стояла защита от повторной загрузки:

    if (!auditEntityTypesLoaded) { loadAuditEntityTypes(); }

— список разделов запрашивался ровно ОДИН раз за открытие страницы.

Сценарий (воспроизведён по коду шаг за шагом):
1. Открыл вкладку «Журнал» — разделы загрузились (или пусто / только текущие), флаг=true.
2. Отредактировал/создал записи — в audit_log появились новые entity_type,
   но список разделов НЕ перезапросился.
3. Повторно открыл вкладку — loadAuditTab() увидел флаг=true, пропустил загрузку
   разделов -> новые разделы в комбобоксе не появились до F5/перезагрузки страницы.

ИСПРАВЛЕНИЕ (static/js/audit.js, изолированный дифф):
- Убран флаг-кэш auditEntityTypesLoaded (объявление + все чтения/записи).
- loadAuditTab() теперь ВСЕГДА вызывает loadAuditEntityTypes().
- loadAuditEntityTypes(): пересобирает <select> заново (статика «Все разделы» +
  актуальный DISTINCT) — без дубликатов; сохраняет текущий выбор пользователя,
  если раздел ещё существует; при ошибке — toast, список перезапросится при
  следующем открытии вкладки (флага, блокирующего повтор, больше нет).

ПРИЧИНА 2 (НЕ баг кода): «внесённые изменения» в старую базу не доезжают.

- Журнал хранит историю БУДУЩИХ правок. Старая боевая БД, скачанная/восстанов-
  ленная ДО включения в код аудита equipment_work и полноценных сводок
  modes/works, в audit_log этих записей уже не имеет и иметь не может —
  в момент тех правок логирование ещё не было включено. Это не «потерялось»,
  этого никогда не фиксировалось.
- Восстановленная БД актуализируется схемой через init_db() (CREATE TABLE
  IF NOT EXISTS, backup.py:573) — таблица audit_log появится, но ЗАПИСЕЙ в ней
  не будет, пока не начнёшь править записи во вновь развёрнутой базе.
